# 物業管理：批量操作及排序設計（已批准）

## 已核實問題及已做修正

管理列表及詳情頁固定渲染出售、出租兩個摘要；不存在的放盤被錯誤標為「未開放」，價格亦重複該文字。現已在本機改為只顯示實際可見放盤的摘要；保留其真實草稿、公開、來源下架、已售或已租狀態。不修改正式資料或擅自建立另一類放盤。

2026-09-07 正式唯讀聚合結果：目前管理查詢有 304 個至少有一個公開放盤的物業組別；219 個只有售盤紀錄、54 個只有租盤紀錄、31 個有租售紀錄。「有租售紀錄」不代表兩者同時公開。原物業詳情頁 SQL 錯誤由 PR #131 處理，尚待正式部署。

## 建議：一物業一行的表格及勾選工具列

桌面欄位：勾選、相片／樓編／屋苑、出售價格及狀態、出租價格及狀態、實用面積、代理、更新時間、管理。沒有相應放盤的儲存格只顯示破折號；手機改為同一資料的緊湊卡片。編輯頁保留新增售盤或租盤入口，但不以缺少放盤當成下架狀態。

排序由伺服器在分頁前執行：最近更新、樓編、屋苑、實用面積、售價、租金，可升降序；空值置後，樓編作穩定次排序。租金與售價不混在同一價格排序。篩選及排序寫入網址；切換篩選清空勾選。

批量操作第一版只選目前一頁（最多 100 個物業），顯示已選數量。操作包含指定代理、設為公開／草稿／下架、售盤已售、租盤已租。先選出售或出租範圍；全物業下架需明確顯示影響兩類現有放盤。不存在的另一類放盤不會自動建立。

提交前列出樓編、涉及放盤數、原值及新值；缺少權限、缺少必要資料或版本已更新的項目不可提交，必須重新載入核實。逐物業透過現有管理寫入流程、版本檢查、職員權限、來源保護與審計執行，回傳每個物業成功／失败，不把部分成功標作全部成功。成功項目取消勾選，失敗項目保留原因，避免重覆提交成功項目。沒有跨頁全庫一鍵公開或刪除。

## 替代方案

1. 保留現有卡片、只加入排序及勾選：改動較小，但同屏可比較物業較少。
2. 建議使用緊湊表格及批量工具列：更適合日常管理，租售仍屬同一物業。
3. 試算表式逐格編輯：改價效率高，但多欄位誤改及版本衝突處理較複雜，不建議首版。

## 實作及驗證範圍

沿用 TanStack Start、Neon raw SQL、既有 public identity、staff authorization 及 admin_property_manage。新增限定的排序驗證及批次請求邊界，不建立第二套物業資料庫。

測試涵蓋缺少售／租盤、雙盤狀態不同、代理僅可見一側、排序跨頁穩定、價格空值、篩選後勾選重設、版本衝突、沒有另一類放盤、權限拒絕及部分成功。正式批量修改不作測試；資料庫整合使用已批准的可棄置分支。

狀態：用戶已批准；重新設計及顯示修正已在本機實作，尚未部署。批量確認採用不可變快照；處理中阻止同路徑篩選及頁數切換，未知儲存結果會停止後續提交。
