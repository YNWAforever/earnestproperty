# Whole-site SEO audit — 2026-09-06

Scope: every public route in `src/routes`, the shared header/footer, `src/content/seo.ts`,
`src/lib/schema.ts`, `sitemap[.]xml.ts`, `public/robots.txt`, `vercel.ts`. Static code review
of the `claude/seo-audit-ysdnol` branch; no live crawl (no DB in the audit environment).
`npm run test:seo` passes on this commit.

## Verdict

The foundations are unusually solid for a site this size: every page is server-rendered
from a route loader, every public route has exactly one `<h1>` and a self-canonical, images
go through `AppImage` (alt/width/height required), legacy URLs get real 301s, empty
`/transactions` and `/estate-reviews` states are noindexed, and JSON-LD output is escaped
correctly. The defects cluster in five places: the production origin, one soft-404 hole,
the legacy-URL redirect map, social/OG metadata inheritance, and structured-data
completeness.

## P0 — fix before anything else

### 1. The whole site canonicalises to `earnestproperty.vercel.app`

`src/content/seo.ts:3` hardcodes `SITE_URL = "https://earnestproperty.vercel.app"`. That
string feeds every `rel=canonical`, every `og:url`/`og:image`, the sitemap `<loc>`s, the
`Sitemap:` line in `public/robots.txt`, and every JSON-LD `url`. The old site lived on
`www.earnestproperty.com` (see `.lovable/plan.md`, `docs/superpowers/plans/2026-06-19-old-site-migration.md`).
If the custom domain is (or becomes) the live host, every canonical tells Google the
`vercel.app` copy is the real one and the custom domain never consolidates. Even if the
custom domain is not yet attached, this is the single change with the largest blast
radius, so make it env-driven now.

- Action: read `SITE_URL` from `VITE_SITE_URL` (fail `prebuild` if unset in production),
  update `robots.test.mjs`, and once the domain is live add a Vercel redirect from
  `*.vercel.app` to the custom host.

### 2. `/blog/$slug` is an infinite soft-404 space

`src/routes/blog_.$slug.tsx:94-133` never throws `notFound()`; an unknown slug renders
"文章不存在" with HTTP 200, and `:145` still emits a self-canonical for the bogus URL.
Every other dynamic route (`estate.$slug.tsx:73`, `agents_.$slug.tsx:29`,
`castle-peak-road.$segment.tsx:37`, `property.$listingNo.tsx:127`) does this right.

- Action: `if (!article) throw notFound()` in the loader; drop the canonical in the
  no-article head branch.

### 3. Legacy listing redirects were never generated

`src/generated/old-site-redirects.json` is `[]`. So every
`/property-detail/<id>.html` from the old site hits the catch-all
`→ /listings` in `vercel.ts:76`, and `/eng/property-detail/…` chains through two hops.
Google treats mass many-to-one redirects as soft 404s, so the old site's per-listing
equity is being discarded rather than passed to `/property/<listingNo>`.

- Action: run `npm run migration:redirects -- artifacts/old-site-migration/<RUN_ID>`
  against the last import run and commit the JSON; collapse the `/eng/` rule to point
  straight at the final destination.

### 4. Listing detail pages are missing from the sitemap

`src/routes/sitemap[.]xml.ts` lists static pages, estates, blog, agents and corridor
paths, but no `/property/*` URL. Those are the money pages and the only ones carrying
`RealEstateListing` JSON-LD.

- Action: add active listings (status `active`, canonical `public_listing_no`) with
  `updated_at` as `lastmod`; split into a sitemap index if it grows past ~2,000.

### 5. Social metadata inherits the homepage almost everywhere

`__root.tsx:95-98` sets `og:title`, `og:description`, `twitter:title`,
`twitter:description` to the homepage copy unconditionally. Thirteen routes never
override OG (`about`, `agents`, `agents_.$slug`, `blog_.$slug`,
`blog_.editorial-standards`, `disclaimer`, `estate-reviews`, `estate.$slug`, `privacy`,
`terms`, `transactions`, `videos`), and **no route anywhere** overrides the Twitter pair.
Every shared estate page, blog article and agent profile renders the homepage card.
`property.$listingNo.tsx:178` also passes `images[0]` through un-absolutised, and blog
and estate pages never set `og:image` even when a cover exists.

- Action: make `seo()` in `src/content/seo.ts` the required path for every route
  head, and have it emit the OG and Twitter pair from the page title/description, plus
  an absolute `og:image` with the site cover as fallback.

## P1 — high impact

### 6. Header navigation is invisible to crawlers

`SiteHeader.tsx:450` and `:541` render the mega-menu and the mobile sheet only on
interaction; the served HTML contains three header links (`/`, `/listings`, `/about`).
The footer is the only crawlable site-wide nav, and it does not link `/listings`.

- Action: render the mega-menu panels in the HTML and hide them with CSS, or add a
  static `<nav>` list; add `/listings` to the footer.

### 7. Every `VideoObject` is invalid

`src/lib/schema.ts:110-129` omits `thumbnailUrl` (required) and `uploadDate` is `null`
for listing-sourced videos (`videos.tsx:481-487`). The page also emits one
`<script>` per video. YouTube IDs are already parsed, so
`https://i.ytimg.com/vi/<id>/hqdefault.jpg` is free.

### 8. Property JSON-LD misrepresents inventory

`property.$listingNo.tsx:277-279` feeds a `placehold.co` "No Image" URL into
`RealEstateListing.image`; `:434` hardcodes `availability: InStock` regardless of
status; sold/rented listings emit `offers: []`; `RealEstateListing`, `Residence` and
`BreadcrumbList` sit in one `@graph` with no `@id` links; no `dateModified`.

### 9. Listing cards and pagination

- `listings.tsx:1268` substitutes an Unsplash stock photo for photo-less listings with
  the listing title as `alt`, indexing a third-party image as the property.
- `listings.tsx:113-131` canonicalises `?page=2+` to the bare `/listings`, so deep
  result pages drop out of the index. Paginated pages should self-canonicalise (filters
  can still canonicalise to the bare path). No `noindex` on zero-result filter combos.

### 10. Organization / NAP signals

`organizationSchema()` (`schema.ts:48-64`) has no `@id`, `telephone`, `sameAs`
(YouTube URL exists in `site.ts`), `image`, `email`, `addressLocality`, `priceRange`,
`openingHoursSpecification` or `geo`. The last two are blocked on client data
(`site-branches.js:19-52` TODOs). The head-office address is written two different
ways (`site.ts:35` vs `site-branches.js:5`) and phone formatting forks
(`26882988` vs `2688 2988`). `/contact` renders four `RealEstateAgent` nodes across two
scripts with nothing tying branches to the parent.

### 11. Article schema is not rich-result eligible

`blog_.$slug.tsx:183-197`: no `image` (cover is loaded and unused), no `dateModified`,
`publisher` has no `logo`, `author` has no `url`, `datePublished` for the two static
articles is a fixed `2026-06-22`. DB-only articles are also absent from the sitemap
(`sitemap[.]xml.ts:27` only maps the static list).

### 12. Placeholder text on indexable legal pages

`privacy.tsx:29`, `terms.tsx:26`, `disclaimer.tsx:27` render
`生效日期：[待補]　・　最後更新日期：[待補]` and all three are in the sitemap.

### 13. `pageSeo` is not the source of truth it looks like

`pageSeo.listings`, `.shamTseng`, `.castlePeakRoad` titles/descriptions are never
rendered (routes hardcode different strings), `pageSeo.tingKau` is entirely dead, and
`pageSeo.contact.title` is unused. Edits there silently no-op on the most commercial
pages. Either route through `pageSeo` or delete the dead copy.

## What is already right (keep it)

- All head data comes from server loaders; nothing SEO-relevant is fetched client-side.
- One `<h1>` per public route, no heading-level skips, no h1 inside cards.
- Canonical on every route, bare path on filterable pages, enforced by
  `canonical-links.test.mjs`.
- `notFound()` on unknown estate/agent/segment/listing slugs; 301 from legacy listing
  numbers to the canonical `public_listing_no`; `/district/ting-kau` hard-redirects.
- Sitemap uses real `updated_at` for estates and articles and filters unpublished
  estates; empty `/transactions` and `/estate-reviews` are noindexed and omitted.
- `AppImage` requires `alt`, `width`, `height`; `target=_blank` always carries
  `rel="noopener noreferrer"`; no CSS-background heroes; homepage hero is eager with
  `fetchPriority="high"` and a full `srcset`.
- `jsonLdScript()` escapes `<`, `>`, `&` before `dangerouslySetInnerHTML`.
- `<html lang="zh-HK">`, `og:locale=zh_HK`, self-hosted fonts with a single sensible
  preload.
