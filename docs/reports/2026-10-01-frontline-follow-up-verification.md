### Recovery boundary

The reused journal is **per-tab sessionStorage**, keyed by actor/conversation/kind. Reload and route return in the same tab are verified. Tab closure/storage loss/new tab/other device are outside that client guarantee. Existing per-request server idempotency remains; this change does **not** add a conversation-wide or cross-tab unknown reservation barrier. After cold reopening, an authorized operator must inspect current scoped conversation/intent/job/receipt evidence before deciding on another deliberate send. Unknown outcomes require existing authoritative provider/worker reconciliation; never infer that a failed GET means the original send did not happen.

GET only reads persisted intent state. A returned `accepted` is provider acceptance, not delivered/read/acknowledged/human reply. A missing/forbidden record has one opaque response. Failed/cancelled readback causes no automatic send. Staff acknowledgement/help is an internal scoped state change, not a notification on a colleague's phone. Support details retain IDs for diagnostics without daily UUID entry.
