# Independent Task10 analytics review

2026-09-06; audit-20260905 / codex/audit-20260905. Scope: privacy/events/attribution/runtime/GA4 adapter/provider/reporting, successful inquiry conversion call site and root document-boundary integration. No implementation edits, credentials, database calls or real analytics/provider calls.

## Findings

1. **P1: Formatted phone numbers bypass the PII boundary.** `src/lib/analytics/attribution.ts` safeToken permits hyphens/underscores and rejects only eight contiguous digits. Consequently a payload such as `{name:'whatsapp_cta_click',payload:{source:'852-9123-4567'}}` survives privacy.ts and GA4's second validation. Reproduced using the actual `createGa4Adapter` with injected fake gtag/load ports: the resulting event contains source equal to that complete phone number. The same validator protects entity context and several payload dimensions, so the documented phone-shaped-value rejection is incomplete. Reject separated phone-shaped values after appropriate normalization, preferably use field-specific enums/public entity identity formats where available, and add boundary plus adapter regressions for hyphen/underscore country-code forms. This is a latent release blocker when analytics is enabled, not evidence that production data was sent.

2. **P2: Initial business view events are dropped before provider enablement.** `src/lib/analytics/events.ts` useTrackPageView sets its fired ref before calling the initially disabled dispatcher. `src/routes/__root.tsx` renders AnalyticsProvider after the Outlet subtree; its useEffect performs configuration, so a landing page child effect can run first. Listing/estate/article/agent/district view hooks then never retry when configuration becomes enabled; generic page_view still emits, hiding the missing business event. Reproduced with the actual transpiled events module and injected child-before-provider effect scheduling: the hook set fired=true, configuration was enabled, the hook was invoked again, and zero listing_view events reached the fake sink. Configure before those effects or provide a readiness mechanism/validated bounded replay that does not mark fired until dispatch is accepted. Add a real root/provider/page mounting regression, not only isolated provider invocation.

## Review fixes verified (2026-09-06)

Both findings above are fixed in source. `safeToken` now normalizes the permitted hyphen/underscore separators before detecting eight-digit phone-shaped runs; the same rule applies to payload/context identities and approved campaign tokens. Page-view hooks now subscribe to analytics readiness while mounted, attempt dispatch when configuration is enabled, and mark fired only after the dispatcher accepts the validated event. Cleanup removes pending callbacks, so unmounted pages do not replay. Private live-route rejection still applies. No root or package wiring changed.
